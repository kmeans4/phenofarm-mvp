## 3. Summary — highest-impact remaining or new items

1. **Any grower can read, edit, or hard-delete any dispensary** (PF-048). `GET/PUT/DELETE /api/customers/[id]` and `GET /api/customers` are not scoped to a relationship, and the customer edit page loads any id. `userId` is required, so PUT is also a silent no-op (PF-049).
2. **Catalog search drops in-flight filter changes** (PF-076, PF-077). `fetchProducts` returns early while `isLoading` is true, and the mount effect fetches twice. Typing through a slow response leaves the grid on an older query.
3. **Binary blobs in Postgres are still the main egress cost** (PF-002, PF-038, PF-051, PF-091, PF-106, PF-107). Images, logos, and lab PDFs are base64 columns with no size cap. Catalog, product list, cart sync, and order reads then pull those payloads through Neon, the function, and the client.
4. **Messaging still polls and counts unread per conversation** (PF-060, PF-121). Every signed-in user hits `/api/messages/conversations` every 15–30s, and that handler runs one `count` per conversation. Open threads refetch and mark read on a 12s timer.
5. **Hot foreign keys are still unindexed** (PF-003). `Product.growerId`, `Order.growerId` / `dispensaryId`, and `OrderItem.orderId` / `productId` have no `@@index`. Favorites and conversations are indexed; the order and catalog paths are not.
6. **Stripe subscription state can move backwards and stay "pro" after cancel** (PF-021, PF-022). `checkout.session.completed` writes `subscriptionStatus: 'active'` with no event-id guard. `customer.subscription.deleted` keeps `subscriptionPlan`, and the grower dashboard treats `plan === 'pro'` as subscribed.
7. **Checkout can succeed for some growers and then erase the whole cart** (PF-028, PF-089, PF-090). Partial success is HTTP 200 with `issues`. The cart page clears `localStorage` on any OK response, and it can also persist the empty cart before hydration finishes.
8. **THC, CBD, and harvest edits are still discarded** (PF-037). PUT `/api/products/[id]` never writes `thcMin` / `thcMax` / `cbdMin` / `cbdMax` / `harvestDate`, and the edit page does not put them in `initialData`.
9. **Grower-created dispensary users are not linked to the dispensary** (N-001). `POST /api/customers` creates the user and the dispensary row and never sets `User.dispensaryId`. Registration does. The account cannot act as that dispensary, and the generated password is never delivered (PF-050).
10. **`returnUrl` is still an open redirect, and a grower session with no `growerId` still drops the tenant filter** (PF-111, PF-020). Batch and strain create push the query string as-is. Several product, inventory, and upload queries pass `growerId: undefined`, which Prisma omits.
